# agent/ - Python FastAPI AI agent

Local context for the agent unit. Cross-cutting rules live in the root CLAUDE.md.

## Layout

- Entry: run.py -> app.main:app (uvicorn, port 8010). Venv at agent/venv/ (python 3.12).
- One brain, no flag matrix. Packages under app/core/:
  - engine/ - the model-facing loop: loop.py (run_loop, the tool-calling loop; pauses at turn boundaries past its deadline and echoes the transcript), llm_client.py (LLMClient over the OpenAI Responses API; V2LLMClient is a one-release alias), progress.py (trace/progress events), tool_results.py (tool-result truncation).
  - runtime/ - the run machine (one HTTP request = one step of a run: investigate -> propose -> execute -> verify): orchestrator.py (step / advance / the transition table / continue / cancel / the run lock), runs.py (run constructors, mutators, the checkpoint policy, RunView projections), phases/{investigate,propose,execute,verify}.py (execute owns the per-roadmap commits and their retry policy), service.py (RuntimeService, the DI root the routes resolve, + StepContext: auth, trace id, time budget, per-batch reserve, cancel probe), results.py (PhaseOutcome / StepResult), prompt.py (build_turn_context + build_messages/compact_state; prompts/system.md is the system prompt, prompts/phase_*.md the per-phase tails), tools.py (the per-phase tool catalogs; the per-scope `required` strip for roadmap_id happens here, never in registry.py), tool_exec.py (read-tool dispatch + stage-tool parsing), terminal.py (terminal-call interpretation per phase + the clarifier cards), staging.py (batches on the run), sentinels.py (web card sentinels -> RunInput), refs.py (@-refs: hydrate once per run via POST /ai/context/resolve-refs, only uuid-shaped ids go over the wire), scope.py, context_cache.py (per-roadmap overview / memory-notes / project-context caches, workspace overview, LRU that never evicts the run's focus roadmaps), overview.py (handle-map outline, `R{n}.` prefixes for non-focus roadmaps), handles.py, revert.py, summarizer.py (conversation compaction), snapshot.py (durable agent-state snapshot v2 + create-metadata sanitizer), operation_contracts.py, async_bridge.py.
  - memory/ - memory-class session state: pending_plan_manager.py, pending_plan_revision_applier.py, applied_changes_log.py, recent_targets.py, actor_context.py.
  - tools/ - registry.py (the shared operation schema from repo-root schemas/; the backend schema gate greps its `required=` literals, so never reword them), dispatch.py (ToolDispatcher; resolves roadmap_id per call and writes it back onto the call's args), handlers/ (context_query, workspace_query, memory_tools, comment_tools), resolver.py (node-reference resolution).
  - trace/ - store.py, the Redis-backed trace store (`{REDIS_TRACE_KEY_PREFIX}:{trace_id}` hash + `:events` list; per-process buffer flushed in batches; reads hit Redis unless this process holds the trace active and hydrated; InMemoryTraceBackend when no Upstash client is configured and for tests via trace.store.reset_for_tests()).
  - contracts/ (sessions.py = session + wire models, runs.py = SessionScope / RunState / RunBatch / RunCommit / RunView), config.py, session_store.py (sessions + the run lock + side keys), nest_client.py, logging_utils.py, realtime_push.py, trace_context.py, metrics.py, briefs/ - shared infrastructure.
- HTTP routes: app/api/routes/sessions.py (POST create / POST {id}/messages / POST {id}/runs/{run_id}/continue / POST {id}/runs/{run_id}/cancel / GET {id}/traces/{trace_id}/events) over sessions_support/{flows,auth,errors,runtime}.py; app/api/routes/briefs.py is the brief generator. Create requires auth (401 AUTH_REQUIRED) and stores owner_key; every other route 404s on an owner mismatch. Error codes the web switches on: SESSION_NOT_FOUND, SESSION_SCOPE_NOT_FOUND, RUN_IN_PROGRESS (409, carries `run`), RUN_NOT_FOUND, RUN_NOT_CONTINUABLE (409, carries `run`). A message without `capabilities: ["continue"]` runs in legacy sync mode (one request, batches past the reserve are SKIPPED_BUDGET).
- Commits happen inside the execute phase (app/core/runtime/phases/execute.py), one per roadmap batch, each with its own revision token + idempotency key, carrying session_id/run_id (only when uuid-shaped: the backend DTO validates them with @IsUUID).
- Tunables live in app/core/config.py (pydantic-settings): AGENT_V2_MAX_TURNS, AGENT_V2_MAX_TOOL_CALLS, OPENAI_V2_* knobs, OPENAI_MODEL_TIMEOUT_SECONDS, SESSION_TTL_SECONDS, AGENT_SUMMARY_* knobs, and the run budget: AGENT_RUN_STEP_BUDGET_SECONDS (soft, the loop pauses at turn boundaries past it; verify skips its model call past it), AGENT_RUN_HARD_DEADLINE_SECONDS (per request), AGENT_RUN_MAX_STEPS, AGENT_RUN_LOCK_TTL_SECONDS, AGENT_RUN_TRANSCRIPT_TTL_SECONDS, AGENT_DIRECT_EDIT_MAX_OPERATIONS[_FOCUS] (the checkpoint policy), AGENT_EXECUTE_MAX_TURNS/TOOL_CALLS, AGENT_MAX_LOADED_ROADMAPS, AGENT_MAX_REFS_PER_MESSAGE, REDIS_TRACE_KEY_PREFIX, AGENT_TRACE_TTL_SECONDS, AGENT_TRACE_FLUSH_EVERY_EVENTS / _INTERVAL_SECONDS. All clamped numbers, never on/off switches.
- Budget invariant: execute starts a batch only when elapsed + reserve <= AGENT_RUN_HARD_DEADLINE_SECONDS. The reserve is OPENAI_MODEL_TIMEOUT_SECONDS + 3 x NEST_TIMEOUT_SECONDS for batches that may still call the model (materialize, proposal/revert preview repair) and 3 x NEST_TIMEOUT_SECONDS for a direct stage_edits batch. Keep NEST_TIMEOUT_SECONDS small (20): at 90 the full reserve exceeds the hard deadline and no proposal batch can ever start.
- Session state: app/core/session_store.py - Upstash Redis with CAS semantics. Memory-class state (pending plan, recents, change history, run, run_history) is snapshotted into roadmap_ai_sessions.metadata.agent_state (see root CLAUDE.md for the memory architecture).
- app/core/nest_client.py calls back into the NestJS backend (roadmap-keyed `/roadmaps/{id}/ai/*` plus the user-scoped `/ai/context/*` family and `/workspaces/{id}`); app/core/tools/registry.py resolves the shared schema from repo-root schemas/.

## Logs - see what the agent actually did

`agent/logs.txt` is the local run log (gitignored). It is written because agent/.env sets `AGENT_LOG_FILE=logs.txt`; `AGENT_LOG_TO_CONSOLE=true` mirrors it to stdout. READ THIS FILE FIRST when debugging agent behavior - it is far faster than reasoning about the code, and it shows what the model actually received and did.

- Every request ends with a human-readable `AI REQUEST: <TITLE>` lifecycle block (built in logging_utils `_build_lifecycle_block`, flushed when the `message_completed` event fires). One block per request (message or continue), covering: ACTOR, ROUTING, TOOL CALL, LLM OPERATIONS, response mode, staged-op counts, token usage, and the assistant reply.
- Useful greps: `AI REQUEST` (request boundaries), `cache ` (prompt-cache hit rate), `run_started` / `run_step_completed` (run + step boundaries: run_id, phase, run_next, run_status), `route_lane=run_<phase>_<outcome>` (e.g. `run_investigate_budget` = the loop ran out of turns/tool calls, `run_investigate_paused` / `run_execute_paused` = the step returned next=continue, `run_verify_verified` = a completed run), `checkpoint_policy` (why an edit executed directly or went to a proposal), `refs_resolved` / `refs_resolve_failed` (@-refs), `reasoning_effort_selected` (adaptive-effort escalation + trigger), `commit_started` / `commit_completed` / `commit_failed` (per-roadmap commits), `run_changes_guard_failed` (the resume guard could not read /ai/context/changes), `verify_completed`, `provider_failure`.
- The `cache` line renders `cached/input (NN%)`. Cached input bills at ~10%, and app/core/runtime/prompt.py `compact_state` deliberately orders the prompt so the static prefix stays byte-stable. A multi-turn conversation sitting at 0% means something per-turn crept ABOVE the `# Actor` block and broke the cacheable prefix - treat it as a regression, not noise (tests/test_runtime_prompt.py `CacheInvariantTests` pins it).
- Message/tool CONTENT is redacted unless `AGENT_LOG_INCLUDE_CONTENT=true`. Turn it on locally when you need the actual prompt or tool payloads; leave it off otherwise.
- To capture a clean run: empty logs.txt, restart the agent, do the one thing you are debugging, then read the file. Old traces are not pruned, so a stale file makes it easy to read the wrong turn.

## Tests

- Run from the REPO ROOT: `node scripts/test_agent_unit.mjs [tests.module_name ...]` (e.g. tests.test_engine_loop). With no arguments it DISCOVERS and runs every tests/test_*.py module - do not reintroduce a hand-maintained allowlist (the old one had silently drifted to skipping 22 of 37 modules). If venv autodetect fails (it does in some non-interactive shells), set AGENT_PYTHON_BIN=agent/venv/Scripts/python.exe.
- If a new test HANGS, delete it rather than retry-looping - flaky agent tests are dropped, not debugged (standing team rule).
- tests/__init__.py forces AGENT_LOG_LEVEL=WARNING for the test process (the runner copies agent/.env, whose DEBUG level made the verbose run overflow spawnSync's 1 MB buffer and surface as "Unable to run Python tests"). Set AGENT_TEST_LOG_LEVEL=DEBUG to see the event blocks while debugging one module.
- tests/runtime_fakes.py holds the shared fakes (MemoryStore with the run lock + side keys, FakeNest, the scripted FakeLLM patched into every phase). tests/test_runtime_smoke_contract.py boots the real FastAPI app under TestClient with those fakes and asserts the HTTP wire contract (create bodies, messages, continue, cancel, trace read, owner 404s) - extend it when a route or response field changes.
- Contract tests: tests/test_operation_contracts.py must pass after any schemas/roadmap-ai-operations.json change - follow the /api-contract skill for the full workflow.
- Before pushing agent/ or schemas/ changes, run the canary: `node scripts/validate_agent_canary_matrix.mjs`.
